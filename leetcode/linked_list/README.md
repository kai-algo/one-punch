# 链表（Linked List）

## 核心思想

链表题没有下标，一切都靠**指针**。写之前先想清楚三件事：

1. **每一步要改哪几个指针、顺序是什么**（改之前先存好 `nxt`，否则断链后找不到后面）；
2. **头节点会不会变**：会变就用 `dummy` 哨兵节点，省掉对头节点的特判；
3. **边界**：空链表、单节点、走到 `None` 时能不能再取 `.next`。

## 三类套路

### 1. 改指针（206、21、25）
- 206 是基础，25 是在它上面加「数够 k 个、接回前后」。
- 21 的重点是 `dummy`：不用判断谁当头。
- 共同点：**先存后继，再改指针，最后移动游标**。

### 2. 快慢指针（141、142）
- 141 判断有没有环；142 在此基础上求入环点。
- 142 的数学：设头到入环点为 `a`，入环点到相遇点为 `b`，环长 `c`，
  相遇时 `2(a+b) = a+b+n*c`，得 `a = (n-1)*c + (c-b)`，所以两个指针分别从 `head` 和相遇点出发必在入环点相遇。

### 3. 数据结构设计（146）
- 单靠哈希表找得快但不能维护顺序，单靠链表维护顺序但找不快，**两者拼起来才是 O(1)**。
- 链表为什么必须是双向：删除任意节点需要 O(1) 拿到前驱。
- 节点里为什么要存 `key`：淘汰尾节点时要反查并删除哈希表里的项。

## 各题易错点

### 206. 反转链表
- 顺序：`nxt = cur.next` → `cur.next = pre` → `pre = cur` → `cur = nxt`，调换会丢链。
- 返回的是 `pre`（循环结束时 `cur` 是 `None`）。

### 21. 合并两个有序链表
- 循环结束后别忘了 `cur.next = list1 or list2`，直接接上剩余整段，不用再逐个比较。
- 返回 `dummy.next`，不是 `dummy`。

### 141. 环形链表
- 标准写法：两个指针都从 `head` 出发，**先移动再比较**，循环条件 `fast and fast.next`，不需要特判空 / 单节点。
- 判断节点相同用 `is`，不要用 `==`。

### 142. 环形链表 II
- `{}` 是空字典，空集合要写 `set()`。
- 判断节点相同要按对象（`is` / 放进 `set`），不能按值，值可能重复。
- 快慢指针版：相遇后让一个指针回到 `head`，**两个都走 1 步**再找入环点。

### 25. K 个一组翻转链表
- 翻转前必须先确认后面有 k 个节点，不够就保持原样。
- 每组翻转后要记住新头（接到上一组后面）和新尾（留给下一组去接）。
- 翻转前先存 `nxt`；技巧：翻转时让 `prev` 初值 = `nxt`，尾节点自动接上下一组。

### 146. LRU 缓存
- 方法名前的 `_`：Python 约定的「内部辅助方法」，不强制。
- 把链表操作拆成 `_remove` + `_add_to_head`，**「移动」要自己组合成摘下 + 插入**，漏掉 `_remove` 不报错，只会悄悄弄乱链表。
- 命中判断用 `key in cache`，不能用 `if not value`（value 可能是 0）。
- 淘汰顺序：先取 `tail.prev.key` 删字典，再摘节点。
- 线程安全：`get` 也会改链表，也要加锁；锁要覆盖「查字典 + 改链表 + 改字典」整个过程。

## 共同的技巧

- **`dummy` 哨兵节点**：头节点可能变（21、25）或需要统一插入删除逻辑（146）时使用。
- **先存后继再改指针**：几乎所有改指针的题都适用。
- **写代码前先画图**：标出每一步改哪几个指针，再动手。
- **链表题测试辅助**：每个文件自带 `ListNode`、`build`、`to_list`，方便用 `==` 比较。
