# 前后缀分解（Prefix / Suffix Decomposition）

## 核心思想

当位置 `i` 的答案**同时依赖「左边的信息」和「右边的信息」**，且两部分互不影响时：

1. 把一个双向约束拆成两个单向约束；
2. 正向扫一遍，得到 `left[i]`（只依赖 `0..i-1`，可由 `left[i-1]` 递推）；
3. 反向扫一遍，得到 `right[i]`（只依赖 `i+1..n-1`，可由 `right[i+1]` 递推）；
4. 把两边**合并**得到答案。

三道题的骨架一样，区别只在「合并」这一步。

## 识别信号

- 问题是「对每个位置求一个值」；
- 这个值依赖左边某种聚合（最大值、乘积、和、计数……）和右边某种聚合；
- 暴力做法对每个位置扫两侧，是 O(n²)。

## 三道题对比

| 题 | 难度 | 左信息 | 右信息 | 合并方式 | O(1) 空间优化 |
|---|---|---|---|---|---|
| [135. 分发糖果](135_candy.py) | 困难 | 左规则要求的糖果数 | 右规则要求的糖果数 | `max` | 上坡 / 下坡分段，维护 `inc`、`dec`、`pre` |
| [238. 除自身以外数组的乘积](238_product_of_array_except_self.py) | 中等 | 左边所有数的积 | 右边所有数的积 | `×` | 结果数组当 `left`，用变量 `r` 滚动记录右侧乘积 |
| [42. 接雨水](42_trapping_rain_water.py) | 困难 | 左边最高柱子 | 右边最高柱子 | `min`，再减自身高度 | 双指针（较矮一侧的水位可确定）；或单调栈（另一思路） |

## 各题特性与易错点

### 135. 分发糖果
- 双向约束最直观的例子：左规则、右规则分别扫一遍，取 `max` 才能同时满足。
- 只看左边会在严格递减序列上出错（如 `[5,4,3,2,1]`）。
- O(1) 版本的难点在「峰顶」：下坡长度追上上坡长度时，峰顶要多补 1 颗。

### 238. 除自身以外数组的乘积
- 最干净的前后缀模板：没有比较和修正，纯粹是 `left[i] × right[i]`。
- 不能用「总乘积 ÷ nums[i]」，因为有 0；前后缀乘法天然避开除 0。
- O(1) 版本：先乘 `r`，再更新 `r`（顺序不能反，因为要排除自身）。

### 42. 接雨水
- 水位由两侧最高柱子中**较矮的一个**决定：`min(left_max, right_max) - height[i]`。
- `left` / `right` 不含自身时，差值可能为负，需要 `max(..., 0)`；含自身则不需要。
- 同一题有三种视角：前后缀数组、双指针、单调栈。

## 共同的优化套路

`left[]`、`right[]` 两个数组 → 滚动变量。因为递推只依赖前一项，用完即可丢弃，空间从 O(n) 降到 O(1)。
