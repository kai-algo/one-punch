# 栈（Stack）

## 核心思想

栈是**后进先出（LIFO）**：最近压入的元素最先被处理。当问题具有「**最近的未完成事项要最先结算**」的结构时，就用栈。

## 一、基础栈

### 识别信号

- 出现「配对 / 嵌套」：后出现的要先闭合；
- 运算对象在运算符**之前**出现，需要暂存，等运算符来了再取出；
- 需要在 O(1) 内拿到栈中某种聚合信息（如最小值）。

### 三道题对比

| 题 | 难度 | 栈里存什么 | 何时弹栈 | 关键点 |
|---|---|---|---|---|
| [20. 有效的括号](20_valid_parentheses.py) | 简单 | 未闭合的左括号（或它期待的右括号） | 遇到右括号 | 右括号来时栈空 / 类型不匹配 → 无效；结束时栈必须为空 |
| [155. 最小栈](155_min_stack.py) | 中等 | 每个状态下的「当前最小值」（辅助栈，或元素与最小值成对存） | `pop` 时主栈、辅助栈同步弹出 | 最小值随栈深度变化，弹出后要能回退到之前的最小值 |
| [150. 逆波兰表达式求值](150_evaluate_reverse_polish_notation.py) | 中等 | 已算出的操作数 | 遇到运算符，弹出两个数 | 减、除的**顺序**（次栈顶 op 栈顶）；除法向零截断 |

### 各题特性与易错点

#### 20. 有效的括号
- 失败有三种：栈空时遇到右括号、类型不匹配、结束时栈非空。最后一种最容易漏。
- 小优化：奇数长度直接返回 `False`。

#### 155. 最小栈
- 本质是**空间换时间**：每一层都记住「到这一层为止的最小值」，pop 时自然回退。
- 重复的最小值要处理：若辅助栈只在 `val < min` 时才压入，遇到相等值会在 pop 时出错，应使用 `<=`，或每次都同步压入。

#### 150. 逆波兰表达式求值
- 先弹出的是**右**操作数，后弹出的是**左**操作数：`a = pop()` 是右、`b = pop()` 是左，结果 `b op a`。
- Python 的 `//` 向下取整，对负数与题目「向零截断」不一致，应使用 `int(b / a)`。
- 负数 token（如 `"-11"`）以 `-` 开头，不能只看首字符判断是不是运算符。

## 二、字符串和表达式解析

### 识别信号

- 输入是一个**字符串**，需要从左到右逐字符 / 逐 token 扫描解析；
- 结构上有「**层级 / 嵌套 / 优先级**」：遇到某个符号要「暂存当前状态、进入新一层」，层结束时「恢复之前状态并合并」；
- 与「一、基础栈」的区别：这里栈存的不只是一个值，而是**一整层的上下文**（半成品字符串 + 重复次数、已累加的结果、目录路径等），而且要自己处理多位数字、空格、分隔符。

### 三道题对比

| 题 | 难度 | 栈里存什么 | 何时弹栈 | 关键点 |
|---|---|---|---|---|
| [71. 简化路径](71_simplify_path.py) | 中等 | 当前有效的目录名 | 遇到 `..` 弹出一个目录 | 按 `/` 切分后逐段处理：空串和 `.` 跳过，`..` 在栈空时忽略，其余入栈；结果以 `/` 拼接并加前缀 `/` |
| [394. 字符串解码](394_decode_string.py) | 中等 | 进入 `[` 之前的（半成品字符串，重复次数） | 遇到 `]` | 数字可能是多位；`[` 时保存现场并清空，`]` 时 `上一层字符串 + 当前串 * k` |
| [227. 基本计算器 II](227_basic_calculator_ii.py) | 中等 | 待累加的项（乘除已就地结算） | 扫描结束统一求和（栈不需要弹，直接 `sum`） | 记录「上一个运算符」，遇到下一个运算符或末尾时才结算当前数字；乘除对栈顶就地计算 |

### 各题特性与易错点

#### 71. 简化路径
- 先 `split('/')` 再处理，比逐字符扫描省心：连续斜杠产生的空串直接跳过。
- `...`、`..hidden` 是合法名称，只有恰好等于 `.` 或 `..` 才有特殊含义。
- `..` 遇到栈空要忽略（根目录没有上一级）；全部回退后结果必须是 `"/"` 而不是空串，`'/' + '/'.join(stack)` 天然满足。

#### 394. 字符串解码
- 数字是多位的（`100[a]`），要边读边累积：`num = num * 10 + int(c)`，不能只取一位。
- 遇到 `[`：把 `(当前字符串, num)` 压栈，然后**重置**当前字符串和 `num`；遇到 `]`：弹出 `(prev, k)`，当前串变成 `prev + 当前串 * k`。
- 字符串不是一进栈就能确定的，必须等 `]` 才能知道要重复多少次——这是栈的「延迟结算」。
- 也可以用递归解析（每层 `[` 递归一次），本质上是在用系统调用栈。

#### 227. 基本计算器 II
- 核心技巧：用 `sign`（上一个运算符）延迟结算。读完一个数字后，根据 `sign` 决定：`+` 压 `num`，`-` 压 `-num`，`*` / `/` 与栈顶合并。
- 最后一个数字后面没有运算符，要在**字符串末尾**也触发一次结算（常见写法：`i == len(s) - 1` 时一并处理）。
- 除法向零截断：对栈顶用 `int(top / num)`，不要直接 `//`（负数向下取整，比如 `-7 // 2 == -4`）。
- 空格要跳过，但**不能**用「遇到空格就结算」，否则 `"3 + 5"` 会提前触发。
- 空间优化：只需保留「当前项」和「已累加和」，栈可以省掉，空间 O(1)。

## 共同模式

「压入 → 等待触发条件 → 弹出结算」：栈保存的是**尚未结算的状态**，触发条件到来时才处理栈顶。各题区别只在：存什么、什么触发、怎么结算。
