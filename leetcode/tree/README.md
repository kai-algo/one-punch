## 二、遍历与树的属性

核心：用某种遍历顺序访问节点，并在遍历中收集或计算树的属性（深度、路径和、可见节点、重建结构）。
这一类的第一个决策永远是：**信息是自顶向下传，还是自底向上返回？**

### 两种视角

| 视角 | 做法 | 典型代码形态 |
|---|---|---|
| 自顶向下（先序，「递」时带参数） | 把已知信息通过参数传给孩子 | `dfs(node, depth)` / `dfs(node, remain)` |
| 自底向上（后序，「归」时返回值） | 子树先算出结果，父节点再合并 | `return 1 + max(dfs(l), dfs(r))` |
| 层序（BFS） | 按层处理，每层是一个批次 | `for _ in range(len(queue))` |

### 四道题对比

| 题 | 难度 | 主要套路 | 信息流向 | 一句话 |
|---|---|---|---|---|
| [104. 二叉树的最大深度](104_maximum_depth_of_binary_tree.py) | 简单 | DFS（后序）/ BFS 数层数 | 自底向上返回 | `1 + max(左, 右)`；也可自顶向下带 `depth` 维护全局最大 |
| [112. 路径总和](112_path_sum.py) | 简单 | DFS 自顶向下 | 向下传「剩余目标值」 | 只在**叶子**处判断 `remain == node.val` |
| [199. 二叉树的右视图](199_binary_tree_right_side_view.py) | 中等 | BFS 取每层最后一个；或「右优先」DFS | 按层 / 按深度 | 每个深度第一次被访问到的节点（右优先）就是可见节点 |
| [105. 从前序与中序遍历序列构造二叉树](105_construct_binary_tree_from_preorder_and_inorder_traversal.py) | 中等 | 分治 + 哈希表 | 向下传区间 | 前序定根，中序定左右子树大小 |

### 各题特性与易错点

#### 104. 最大深度
- 最基础的「树的属性」题，空树深度为 0。
- 两种写法都要会：后序返回值（简洁）、自顶向下带参数（为后面的「带状态 DFS」打基础）。
- BFS 写法：层数 = 外层循环次数。

#### 112. 路径总和
- 易错点 1：必须是**根到叶子**。`[1,2]`, `target=1` 应为 False，因为 1 不是叶子。
- 易错点 2：不能在和超过 `target` 时剪枝——节点值可以为负。
- 易错点 3：空树直接 False，即使 `target == 0`。
- 叶子判断：`not node.left and not node.right`，不要只判断 `not node`。

#### 199. 右视图
- 本质是「每一层的最后一个节点」。
- BFS：记下每层 `len(queue)`，取该层最后一个。
- DFS：先右后左，`depth == len(res)` 时第一次到达该层，记录当前节点。
- 易错点：右子树不够深时，左子树更深的部分也会被看到，不能只沿右孩子走。

#### 105. 前序 + 中序建树
- 前序第一个是根；在中序里找到根的位置，左边是左子树，右边是右子树。
- 用哈希表 `val -> 中序下标`，把每次找根从 O(n) 降到 O(1)，整体 O(n)。
- 左子树大小 `left_size = root_idx - in_left`，据此划分前序区间；这是最容易算错的地方。
- 建树顺序要先左后右（前序消费顺序），否则指针对不上。
- 传下标区间而不是切片，避免 O(n²) 拷贝。

### 本类共性小结

- **题型识别**：问的是「整棵树的某个数」或「一组节点」，而不是修改树的形状。
- **写代码前先回答**：这个信息是从父传给子，还是从子传给父？
- **叶子 vs 空节点**：112 要求叶子判定，104 的终止条件是空节点，别混用。

## 三、二叉搜索树（BST）

核心：BST 的性质是 **左子树所有值 < 根 < 右子树所有值**，由此得到两个武器：
1. **中序遍历是严格递增序列**（230）；
2. **每一步比较大小就能决定走左还是走右**，不用搜索整棵树，单次操作 O(h)（235、450）。

做 BST 题第一步：想清楚是用「中序有序」还是「比大小定方向」。

| 题 | 难度 | 利用的性质 | 一句话 |
|---|---|---|---|
| [230. 二叉搜索树中第 K 小的元素](230_kth_smallest_element_in_a_bst.py) | 中等 | 中序有序 | 中序遍历计数，数到第 k 个就停（可提前终止） |
| [235. 二叉搜索树的最近公共祖先](235_lowest_common_ancestor_of_a_binary_search_tree.py) | 中等 | 比大小定方向 | 从根往下走，p、q 都比当前小就往左，都比当前大就往右，否则当前就是 LCA |
| [450. 删除二叉搜索树中的节点](450_delete_node_in_a_bst.py) | 中等 | 比大小定方向 + 结构调整 | 先按大小找到节点，再分 0/1/2 个孩子三种情况处理 |

### 各题特性与易错点

#### 230. 第 K 小的元素
- 中序遍历 = 升序，第 k 个访问到的节点就是答案；递归（带计数器）或迭代（显式栈）都要会。
- 迭代写法可以在第 k 个时直接返回，不必遍历完整棵树。
- 进阶（频繁修改 + 频繁查询）：每个节点额外维护子树大小 `size`，查询时比较左子树大小与 k，O(h)。

#### 235. 最近公共祖先
- 不需要像普通二叉树（236）那样回溯，BST 的大小关系已经告诉你方向，迭代即可，O(h) 时间 O(1) 空间。
- 终止条件：`p.val <= cur.val <= q.val`（先令 p < q），即 p、q 分居两侧或其一等于当前节点。
- 易错点：节点可以是自己的祖先（p 本身就是 LCA 的情况）；不要假设 `p.val < q.val`。

#### 450. 删除节点
- 先按大小找 key，找到后分三种情况：
  - 叶子：直接删（返回 `None`）；
  - 只有一个孩子：用孩子顶替；
  - 两个孩子：用**右子树最小节点（后继）**顶替，或把左子树挂到后继的左边。
- 易错点 1：递归写法要接住返回值：`root.left = self.deleteNode(root.left, key)`。
- 易错点 2：后继节点自己可能带右子树，不能简单"复制值"后忘了删原后继。
- 易错点 3：合法答案不唯一（用前驱或后继都可以），测试不要比较形状，要校验「仍是 BST + 中序序列正确」。

### 本类共性小结

- **能走一条路就不要遍历整棵树**：搜索/插入/删除/LCA 都是沿一条根到叶的路径，O(h)。
- **想要有序就用中序**：第 K 小、验证 BST、两节点最小差等都是中序遍历的变体。
- **删除/插入要返回根**：修改树结构的递归函数，返回值就是「这棵子树新的根」。

## 四、实际应用与综合结构

核心：把树的思想用到「真实场景」或「更复杂的结构」上——前缀树存字符串、树形 DP 做决策、
前缀和 + 回溯统计路径。不再是单纯的遍历，而是**在树上维护额外的状态**。

| 题 | 难度 | 套路 | 在树上维护什么 |
|---|---|---|---|
| [208. 实现 Trie (前缀树)](208_implement_trie_prefix_tree.py) | 中等 | 多叉树 + 结束标记 | 每个节点：26 个孩子 + `is_end` |
| [337. 打家劫舍 III](337_house_robber_iii.py) | 中等 | 树形 DP（后序） | 每个节点返回 `(偷, 不偷)` 两个值 |
| [437. 路径总和 III](437_path_sum_iii.py) | 中等 | 前缀和哈希 + 回溯 | 根到当前节点的前缀和计数表 |

### 各题特性与易错点

#### 208. Trie
- 节点结构：`children`（字典或长度 26 的数组）+ `is_end`。三个操作都是沿着字符一路向下走。
- `search` 与 `startsWith` 的区别只在最后：前者还要 `is_end`，后者只要路径存在。
- 易错点：插入 `apple` 后 `search("app")` 必须为 False（没有结束标记就不是单词）；查询中途缺少孩子要立即返回 False。

#### 337. 打家劫舍 III
- 每个节点返回 `(rob, not_rob)`：
  - `rob = node.val + left.not_rob + right.not_rob`；
  - `not_rob = max(left) + max(right)`。
- 不能简单"隔层偷"：偷了当前节点，孩子不能偷；但**不偷当前节点时，孩子也不是必须偷**，要各自取最大值。
- 朴素递归（偷根时加四个孙子）会重复计算，需要记忆化，返回二元组可直接避免。
- 与 198/213 的区别：状态依赖从「前一个」变成「左右子树」，所以用后序合并。

#### 437. 路径总和 III
- 暴力：对每个节点作起点做一次 DFS，O(n²)（最坏链状）。
- 优化：前缀和 + 哈希表，进入节点时 `cur += val`，答案加上 `cnt[cur - target]`，再 `cnt[cur] += 1`，递归完后**回溯** `cnt[cur] -= 1`。
- 易错点 1：哈希表初始要有 `cnt[0] = 1`（路径从根开始的情况）。
- 易错点 2：先累加答案、再把当前前缀和计入，否则 `target = 0` 时会把自己算进去。
- 易错点 3：回溯不能漏，否则兄弟子树会误用别的分支的前缀和。
- 节点值可为负、路径可不以叶子结束，不能剪枝。

### 本类共性小结

- **状态跟着递归走**：208 状态在节点里，337 状态靠返回值，437 状态靠全局表 + 回溯。
- **后序返回多个值** 是树形 DP 的标志；**进入时加、离开时撤销** 是路径统计的标志。
- 同样是「路径」，112 是根到叶子，437 是任意向下路径，注意与 112 的区别。
